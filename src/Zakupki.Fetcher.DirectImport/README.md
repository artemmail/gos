# Прямой импорт из ЕИС в SQL Server

Утилита повторяет поиск `fetch.py`: перебирает регионы, даты и четыре типа уведомлений 44-ФЗ, оставляет XML с IT-ключевыми словами и сохраняет закупки напрямую в таблицы приложения. Для записи используется существующий `NoticeProcessor`: он обновляет `Notices`, `NoticeVersions`, `ProcedureWindows` и метаданные `NoticeAttachments`. Каталог `out` и `manifest.tsv` не создаются.

Параметры опроса находятся в [appsettings.json](appsettings.json). `AutoCalculateDays: true` включает автоматический расчёт периода докачки и применяется по умолчанию, в том числе если поле отсутствует в старом файле настроек. Утилита проверяет все настроенные регионы и повторяет цикл через 60 минут после его завершения. В начале цикла выводятся рассчитанный диапазон, число дат и окон загрузки. Изменения файла применяются перед следующим циклом. `RunOnce: true` выполняет один цикл и завершает работу.

Прогресс хранится в таблице `ImportBatches` той же БД отдельно для каждой даты, региона, типа документа и режима загрузки пакетов. Начальная дата фиксируется перед первым запросом. После перезапуска утилита обрабатывает все пропущенные даты от этой границы, даже если простой превышает `Days`. Ошибка скачивания, разбора XML, записи в БД или загрузки пакета оставляет окно незавершённым для следующего цикла. День текущего запуска также остаётся незавершённым до повторной проверки в следующие сутки, чтобы получить документы, опубликованные после последнего опроса. Завершённые даты в пределах `Days` перепроверяются для получения запоздавших публикаций. Увеличение `Days` расширяет начальную границу назад.

Для региона без журнала начальная дата вычисляется по последнему сохранённому импорту в этом регионе (`NoticeVersions.LastSeenAt`, с переводом UTC в местную дату). День последнего импорта включается целиком. `Days` задаёт минимальную глубину проверки; при `Days: 14` это 15 календарных дат, включая сегодня. Если последняя загрузка была месяц назад, период автоматически расширится до месяца. Для региона с пустой историей используется `сегодня − Days`. Для старых запусков до появления журнала такой расчёт является оценкой по сохранившимся записям. После сохранения начальной границы новые записи в БД сохраняют эту границу, и все незавершённые даты продолжают участвовать в докачке.

`AutoCalculateDays: false` задаёт ручной период от `сегодня − Days` до сегодня. Журнал сохраняется; после включения автоматического режима в загрузку снова включаются все более ранние незавершённые даты.

При повторной обработке одинаковые данные пропускаются, версии извещения с разными внешними ID сохраняются в одной карточке закупки. История включает старые версии, актуальная карточка формируется по последней версии. SQL-блокировки сериализуют запись одной закупки и запуск нескольких экземпляров утилиты в одну БД. Ранее созданные дубли требуют отдельного объединения с сохранением связанных данных.

Запуск из каталога `src`:

```powershell
dotnet run --project Zakupki.Fetcher.DirectImport
```

При запуске из Visual Studio утилита находит файлы конфигурации относительно каталога `src`; файл настроек импорта также копируется в выходной каталог. Перед первым запуском замените заглушку `PUT_YOUR_TOKEN_HERE` в `Zakupki.Fetcher/appsettings.json` или заполните `DirectImport:Token` в настройках утилиты.

Проверить HTTPS ЕИС без подключения к БД можно командой `dotnet run --project Zakupki.Fetcher.DirectImport -- --check-eis`. Утилита сначала обращается к `int.zakupki.gov.ru`, как `fetch.py`. Для адресов ЕИС принимается сертификат с ошибкой доверия корневому центру (`UntrustedRoot`), если имя узла и остальные проверки сертификата прошли.

В `DirectImport:ConnectionString` скопирована строка подключения из текущего `Zakupki.Fetcher/appsettings.json`. Она использует Windows Integrated Security: отдельного SQL-логина и пароля в ней нет, доступ определяется учётной записью запущенного процесса. Поле `DirectImport:Token` можно заполнить отдельным токеном ЕИС. Если эти поля пустые, используются `ConnectionStrings:Default` и `Zakupki:Token` из конфигурации приложения.

Пример подключения с SQL-логином: `"ConnectionString": "Server=ИМЯ_СЕРВЕРА;Database=ИМЯ_БД;User ID=ЛОГИН;Password=ПАРОЛЬ;Encrypt=True;TrustServerCertificate=True"`. Для секретов можно использовать переменные окружения `DirectImport__ConnectionString` и `DirectImport__Token`. Другой файл конфигурации приложения указывается через `--appsettings PATH`, файл параметров опроса — через `--import-settings PATH`.

`Days: 3` охватывает четыре календарные даты от даты три дня назад до текущей включительно. Если `Regions` отсутствует или содержит пустой массив, используются все регионы из `fetch.py`; например, `[77, 78]` ограничит поиск двумя регионами. `Limit: 0` снимает лимит на число изменённых закупок за цикл. Положительный лимит проверяется после обработки текущего окна, поэтому итоговое количество может превысить лимит на размер этого окна. `FetchByPurchaseNumber: true` дополнительно запрашивает пакет по номеру каждой найденной закупки и импортирует поддерживаемые документы из него. Пакет повторно запрашивается после ошибки и для ранее сохранённого извещения. `PauseBetweenDatesSeconds: 0.4` задаёт паузу после окна одной даты, региона и типа документа. `IntervalMinutes: 60` задаёт паузу после завершения полного цикла. Остановка выполняется через `Ctrl+C`.

Клиент скачивает все `archiveUrl` из ответа ЕИС. Пустой результат считается успешным при явном `noData=true`. Ответы `errorInfo`, SOAP Fault и ответы без результата приводят к повторной загрузке окна в следующем цикле.

Каждый цикл обновляет существующие версии через `NoticeProcessor`. Поиск RI223/223-ФЗ пока не поддерживается XML-моделью приложения. Утилита сохраняет ссылки и метаданные вложений; содержимое файлов можно загрузить через API приложения.

Регрессионные проверки запускаются из `src` командой `dotnet run --project Zakupki.Fetcher/ClientApp/review/direct-import-smoke/Smoke.csproj -p:SkipClientApp=true -- C:/goszak/gos/src/Zakupki.Fetcher.DirectImport/appsettings.json`. Они создают отдельную временную БД на настроенном SQL Server и удаляют её после проверки. Флаг `--live` в конце команды дополнительно проверяет обычную точку входа утилиты на данных ЕИС за вчера и сегодня по региону 77 с записью в эту тестовую БД.
